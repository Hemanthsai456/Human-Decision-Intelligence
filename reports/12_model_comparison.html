Stage 12 — Model Comparison

Hemanth Sai Charagundla

1. Purpose

This stage compares the validation performance of the four candidate models trained in Stage 11:

  1. Logistic regression (GLM)
  2. Generalized additive model (GAM)
  3. Random Forest (Ranger)
  4. XGBoost

The comparison covers discrimination, classification at a fixed threshold, probability quality, calibration, and, for the tree-based models, feature importance. The test set is not used.

2. Prerequisites and Execution Order

Stage 12 depends on the validation results saved by Stage 11.

The required execution order is:

  1. R/01_data_loading.R — load the CPC18 raw dataset.
  2. R/03_data_cleaning.R — create the cleaned analytical dataset.
  3. R/04_data_validation.R — validate logical and structural consistency.
  4. R/05_feature_engineering.R — construct decision-relevant features.
  5. R/10_ml_training.R — create the subject-grouped training, validation, and test sets.
  6. R/11_ml_training_evaluation.R — train the four models and save validation results.
  7. R/12_model_comparison.R — compare the validation results.
  8. reports/12_model_comparison.Rmd — document the comparison.

Stages 06–09 are not required for this stage.

The project root is explicitly set as the working directory before the pipeline scripts are sourced.

3. Load Required Packages

The comparison is implemented in R/12_model_comparison.R, which is sourced here. The script builds the comparison tables and plots used in this report, saves the tables in data/processed/, and saves the plots as PNG files in outputs/model_comparison/.

4. Comparison Strategy

The comparison uses only the validation-set predictions and metrics from Stage 11.

  • Higher is better: accuracy, precision, recall, F1, ROC-AUC, PR-AUC.
  • Lower is better: Brier score, which measures the accuracy of predicted probabilities.
  • Calibration: an intercept near 0 and a slope near 1 are better.

No composite score is built, because these metrics describe different aspects of performance and any weighting would be arbitrary.

7. ROC Analysis

The ROC curves show how well each model separates B choices from A choices across all thresholds. Ranger has the highest ROC-AUC (0.791), and XGBoost is 0 lower. The tree-based models reach 0.79 to 0.791, compared with 0.741 to 0.757 for the GLM and GAM.

8. Precision-Recall Analysis

PR-AUC ranges from 0.795 to 0.796 for the tree-based models and from 0.713 to 0.747 for the GLM and GAM. The two classes are close to balanced, so the precision-recall curves tell a similar story to the ROC curves.

9. Calibration

The dashed diagonal is perfect calibration. Across the four models, calibration slopes are within 0.02 of 1, and intercepts are within 0.03 of 0, so predicted probabilities correspond closely to observed choice rates.

13. Interpretation

The tree-based models predict B choices better than the GLM and GAM on discrimination, precision-recall performance, and probability quality, so nonlinear effects and interactions between the decision variables carry useful information.

The two best models are Ranger and XGBoost. They differ by 0 in ROC-AUC, 0.001 in PR-AUC, and 0 in Brier score. Differences this small, measured on one validation set, do not clearly separate the two models, so no single winner is declared here.

14. Limitations

  • All comparisons use one fixed validation set of participants and carry sampling uncertainty that the tables do not show.
  • The tree-based models use untuned baseline settings, so the ranking may change after tuning.
  • The validation set has now been used to compare models, so its scores are optimistic as estimates of final performance.
  • The split is by participant but not by decision problem, so the results describe prediction for new participants on known problems.
  • Feature importance describes model behavior and is not evidence of causal effects.

15. Next Steps

Before final performance can be reported, the model configuration still needs to be chosen and, if wanted, tuned on training and validation data only. The untouched test set should then be evaluated once, with that final configuration.
